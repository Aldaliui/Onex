# مرجع Odoo وحدود التكامل

تمت مراجعة مستودع [Odoo](https://github.com/odoo/odoo) من الفرع `19.0`، مع تثبيت نسخة مرجعية محلية خارج مستودع ONEX. لا يُنسخ Odoo كاملًا داخل ONEX؛ فـONEX مشروع إعادة بناء مستقل لنظام Oracle Forms/ERP القديم، ويستخدم React/TypeScript وطبقة Cloudflare/D1، بينما Odoo منصة ERP كاملة ذات نموذج بيانات وإضافات مختلفين.

## القرار المعماري

يُستخدم Odoo كمرجع مقارنة لسير العمل التجاري ومفاهيم المحاسبة، وليس كاعتمادية تشغيلية أو مصدر ملفات يُدمج عشوائيًا. أي تكامل مستقبلي يجب أن يكون عبر عقد API أو مزامنة صريحة للبيانات مع تحديد النظام صاحب الحقيقة، وليس عبر نسخ مجلدات `addons` أو جداول Odoo إلى ONEX.

## تحديث هذه المرحلة

أُصلح مسار عكس الفاتورة في نواة Oracle لدى ONEX ليُنشئ قيدًا عكسيًا متوازنًا مرتبطًا بالقيد الأصلي، مع السماح فقط بانتقال الحالة `POSTED → REVERSED` ومنع تعديل بقية بيانات المستند المرحّل. أضيف فحص ثابت يمنع تراجع هذه الضمانات.

## حدود ما لم يُنفذ

لم يتم ترحيل بيانات Odoo، ولم تُستبدل قاعدة ONEX، ولم تُنفذ مزامنة خارجية أو نشر إنتاجي. يلزم قبل أي تكامل فعلي تحديد إصدار Odoo المستهدف، اتجاه المزامنة، خرائط الحسابات والعملاء والأصناف، وسياسة التعارض والـidempotency.
