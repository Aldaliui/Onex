# مصفوفة توافق نوافذ ONEX مع النظام القديم

## النتيجة

تم توليد مصفوفة واحدة لكل **1,490** نافذة من `legacy-source/window_catalog.csv`. المصفوفة تجمع الشاشة والحقول والإجراءات وTriggers والجداول والحزم والتقارير والصلاحيات وحالات الاستخدام، وتفصل بين الدليل المرصود وبين ما يزال مفقوداً.

> هذه ليست مطابقة نهائية. ملفات الكتالوج تستخرج مؤشرات من FMX/PLX ولا تعادل ملفات FMB أو PKS/PKB الأصلية. لذلك لا تُحوّل المؤشرات إلى أسماء حقول أو قواعد عمل مؤكدة.

## الملفات المولدة

- `window-parity-matrix.csv`: صف مستقل لكل نافذة، مناسب للاستيراد إلى Excel أو Sheets.
- `generation-rules.md`: ما تم توليده آلياً وما يتطلب مصدراً أصلياً.

## ما تم توليده

يُولّد لكل نافذة اسم الشاشة القياسي، المجال، عدد الحقول المرصودة، عدد الحقول القياسية في العقد، الإجراءات القياسية، عدد Triggers والإجراءات والجداول، الحزم المرصودة، مؤشر التقارير والطباعة، نطاق الصلاحيات العام، وحالات الاستخدام القياسية.

## ما لا يجوز اختلاقه

لا يمكن من المؤشرات وحدها توليد أسماء الحقول وأنواعها، ولا ترتيب التنقل، ولا نصوص Triggers، ولا علاقات الجداول، ولا قواعد الحزم، ولا صيغ التقارير، ولا حدود الصلاحيات الخاصة بكل دور. هذه العناصر تحتاج ملفات `FMB` و`PLL` و`PKS` و`PKB` و`DDL` وملفات التقارير وبيانات اختبارية.

## معيار اعتماد النافذة

تنتقل النافذة من `CATALOG_ONLY` إلى `SPEC_ONLY` بعد توثيق الحقول والقواعد، ثم إلى `IN_PROGRESS` بعد بناء التنفيذ، ولا تصبح `VERIFIED` إلا بعد مقارنة القراءة والحفظ والتعديل والإلغاء والترحيل والعكس والطباعة مع النظام القديم على بيانات متطابقة.

## الأولوية المقترحة للتوليد

يبدأ التوليد التفصيلي من النوافذ ذات الصلة بدورة الأعمال: فواتير المبيعات والمشتريات، المرتجعات، المخزون، القيود، القبض والصرف، ثم التقارير. بعد ذلك تُستكمل النوافذ الإدارية والاستعلامية.
