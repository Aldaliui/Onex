| الشركة/الفرع | `companies`, `branches` | كل صنف ومستودع يجب أن يكون ضمن tenant scope |
| المستودع | `warehouses`, `warehouse_locations` | الشركة والفرع والصلاحية |
| الرصيد | `stock_balances` | unique(itemId, warehouseId[, locationId]) مع versionNo |
| الحركة | `stock_movements` | receipt, issue, transfer, adjustment, count, reversal |
| المستند | `inventory_documents`, `inventory_document_lines` | فصل رأس المستند عن الأسطر |
| الدفعة/السيريال | `stock_batches`, `stock_serials` | عند وجود مؤشرات BATCH_NO/SERIAL |
| التكلفة | `inventory_cost_layers` | FIFO أو moving average حسب السياسة |
| التدقيق | `audit_events` | actor من الجلسة وليس من body |

## قواعد يجب عدم فقدانها

1. لا تسمح برصيد سالب إلا بسياسة صريحة وصلاحية خاصة.
2. لا تنفذ ترحيل الحركة دون التحقق من الشركة والفرع والمستودع والصنف.
3. استخدم idempotencyKey لكل مستند أو حركة.
4. نفذ تعديل الرصيد وحفظ الحركة والقيد في `env.ONEX_DB.batch()` واحدة.
5. لا تسمح بتعديل حركة مرحّلة؛ استخدم عكساً أو مستند تسوية.
6. خزّن الكمية والتكلفة بصيغة عشرية موحّدة، مع تحقق Worker من NaN/Infinity والقيم السالبة.
7. عالج الصلاحيات الموجودة في المصدر القديم: `PRIVILEGE_WH`, `PRIV_ACC`, الفرع، الشركة، المشروع، والنشاط.
8. لا تعتبر `FMB_PLL_not_found` موافقة على التنفيذ؛ يلزم اختبار قبول ومقارنة مع Oracle عند توفره.
