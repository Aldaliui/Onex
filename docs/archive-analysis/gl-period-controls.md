# مرحلة GL — الأستاذ العام وإغلاق الفترة المالية

تضيف هذه المرحلة ضوابط الأستاذ العام والفترات المالية إلى ONEX Cloudflare-native ERP.

## Migration

```text
cloudflare/d1/0010_gl_period_controls.sql
```

تضيف إلى `journal_entries`:

- `periodId`.
- `reversedJournalId`.
- `postedAt`.
- `description`.

وتضيف جدول:

```text
fiscal_period_closures
```

لحفظ منفذ الإغلاق وتاريخه وعدد القيود وإجمالي المدين والدائن.

## واجهات GL

### إنشاء قيد

```http
POST /api/gl/journals
```

مثال:

```json
{
  "journalNo": "GL-MANUAL-001",
  "entryType": "GENERAL",
  "periodId": 1,
  "description": "Manual adjustment",
  "lines": [
    {"accountCode": "1100", "debit": 100, "credit": 0},
    {"accountCode": "4100", "debit": 0, "credit": 100}
  ]
}
```

يتم رفض القيد إذا:

- لا توجد أسطر.
- الحساب غير موجود أو غير نشط.
- يحتوي السطر على مدين ودائن معاً.
- لا يتساوى مجموع المدين والدائن.
- الفترة غير موجودة أو مغلقة.

### الفترات

```http
GET /api/gl/periods
```

### ميزان المراجعة

```http
GET /api/gl/trial-balance?periodId=1
```

يعرض لكل حساب:

```text
debit
credit
balance
accountType
```

### إغلاق الفترة

```http
POST /api/gl/periods/:id/close
```

يتحقق Worker من توازن جميع القيود المرحّلة في الفترة، ثم يحوّل الحالة من:

```text
OPEN → CLOSED
```

ويحفظ سجل الإغلاق في `fiscal_period_closures`.

### عكس قيد

```http
POST /api/gl/journals/:id/reverse
```

ينشئ قيداً عكسياً يقلب المدين والدائن، ويغير حالة القيد الأصلي إلى `REVERSED`.

لا يمكن عكس قيد بعد إغلاق فترته.

## حماية العمليات التشغيلية

تم ربط ترحيل حركات المخزون وفواتير AR وفواتير AP بفترة GL مفتوحة. عندما تغلق جميع الفترات، يمنع Worker:

```text
FISCAL_PERIOD_CLOSED
```

وبالتالي لا يمكن إنشاء قيد جديد أو ترحيل استلام أو بيع أو شراء بعد الإغلاق.

## نتائج الاختبار

تم اختبار:

- إنشاء قيد متوازن بقيمة 100/100.
- رفض القيد غير المتوازن.
- ظهور القيد في ميزان المراجعة.
- إنشاء قيد عكسي بقيمة 100/100.
- تغيير القيد الأصلي إلى `REVERSED`.
- إغلاق الفترة وتسجيل إحصاءات الإغلاق.
- رفض قيد جديد بعد الإغلاق.
- رفض ترحيل مستند مخزون بعد الإغلاق.
- نجاح `PRAGMA foreign_key_check`.
- نجاح `node --check` و`pnpm check`.

## ملاحظات محاسبية

الإغلاق الحالي يمنع الترحيل التشغيلي الجديد، لكنه لا ينفذ بعد إقفال الأرباح والخسائر إلى حساب الأرباح المحتجزة. هذه خطوة لاحقة تشمل:

1. حساب صافي الإيرادات والمصروفات.
2. إنشاء قيد إقفال الأرباح والخسائر.
3. إنشاء فترة جديدة.
4. ترحيل الأرصدة الدائمة فقط إلى الفترة الجديدة.
