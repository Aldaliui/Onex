# مراجعة مطابقة mido وcloud-onex

**الحالة:** جاهز للمراجعة البشرية، وليس اعتمادًا محاسبيًا نهائيًا.

**مصدر الاختبارات:** مستودع `aldalistor/mido`، الاختبارات التنفيذية `test-accounting-core.js` و`test-invoice-posting-core.js`. تم حفظ متجهات المقارنة في [`test/fixtures/mido/accounting-parity.json`](../test/fixtures/mido/accounting-parity.json)، وتُشغّل آليًا عبر `server/midoParity.test.ts`.

## نموذج الحقيقة

يُعتمد **cloud-onex** مصدرًا لبيانات التشغيل الجديدة والمعاملات التي تُنشأ بعد الترحيل. تُستخدم قواعد mido كمرجع سلوكي مؤقت إلى أن يوقّع مالك المجال المحاسبي على فروق السلوك. لا ينبغي إبقاء Oracle أو Electron مسار كتابة ثانٍ للفواتير أو القيود بعد التحويل النهائي.

## مصفوفة المطابقة

| كيان المصدر في mido | النموذج الموحد في cloud-onex | مفتاح المطابقة | حالة المراجعة |
|---|---|---|---|
| `accountCode` / `accountId` | `accounts.code` / `accounts.id` | الشركة + رمز الحساب | يحتاج مطابقة كتالوج الإنتاج |
| `itemCode` | `items.code` | الشركة + رمز الصنف | يحتاج ربط الحسابات والتكلفة |
| العميل | `customers` | الشركة + `code`، وليس الاسم | يحتاج تنظيف التكرارات |
| المورد | `suppliers` | الشركة + `code`، وليس الاسم | يحتاج تنظيف التكرارات |
| الفاتورة | `invoices` | `docNo` و`idempotencyKey` | مطبق على مسار الإنشاء |
| بنود الفاتورة | `invoice_lines` | `invoiceId` + `itemId` | مطبق على مسار الترحيل |
| القيد | `journal_entries` + `journal_entry_lines` | رقم القيد + المصدر | مطابقة التوازن آلية |
| الفترة المالية | `fiscal_periods` | الشركة + نطاق التاريخ | حارس الترحيل مطبق |
| حركة المخزون | `stock_movements` / `stock_balances` | الصنف + المستودع + المصدر | مطابقة التكلفة تحتاج اعتمادًا |
| التدقيق | `audit_events` | `requestId` الفريد | مطبق في الخدمات الحرجة |

## سياسة العملة

تستخدم الخدمات كائن سياسة موحدًا في `server/erpPolicy.ts`: رمز ISO من ثلاثة أحرف، مقياس عشري معلن، وتقريب `HALF_UP`. لا يجوز اعتماد نتيجة إجمالية محسوبة في React وحده؛ الحساب النهائي يجب أن يبقى في الخدمة/النواة. العملة الأساسية الافتراضية `SAR` ويمكن ضبطها عبر `ONEX_BASE_CURRENCY`، مع إبقاء سعر الصرف موجبًا ومتحققًا قبل الإنشاء.

## فروق السلوك المعروفة

| الموضوع | سلوك mido المرجعي | سلوك cloud-onex الموحد | قرار مطلوب |
|---|---|---|---|
| دقة المبلغ | `Number` مع هامش `EPSILON` | مبالغ الخدمة تتحقق وتُخزن بدقة عشرية، وسياسة التقريب معلنة | اعتماد مالك المجال للمقياس والتقريب |
| حالات المستند | مسارات Electron/محلية متعددة | `DRAFT` ثم `POSTED` ثم `REVERSED` مع معاملات قاعدة بيانات | اعتماد خريطة الحالات النهائية |
| الترحيل | repository adapter في الاختبار | خدمة خادم مع تحقق الفترة والمخزون والتدقيق | اختبار تكامل بقاعدة اختبار |
| الصلاحيات | قواعد mido المحلية | `assertErpAction` على حدود tRPC، مع وضع صارم عبر `ONEX_ENFORCE_PERMISSIONS=1` | تفعيل الوضع الصارم بعد تحميل الأدوار الإنتاجية |
| الترخيص | `commercial-license-core.js` | `assertLicensed` داخل سياسة الخدمة | ربط مصدر الترخيص الإنتاجي وتدوير المفاتيح |
| الحسابات الإنتاجية | أكواد موروثة حسب البيئة | نموذج `accounts` موحد، وحسابات الأطراف مرتبطة بـ`accountId` | اعتماد جدول mapping قبل التحويل |
