# نشر تغييرات `main` بعد اختبارات التطوير

يستخدم المشروع السكريبت `scripts/publish-main.sh` لنشر التغييرات إلى `origin/main` بعد اجتياز فحص TypeScript ومجموعة الاختبارات. السكريبت مصمم ليكون حاجزًا آمنًا قبل الدفع؛ فهو لا ينشر من فرع آخر، ويرفض شجرة عمل غير نظيفة، ويتحقق من آخر نسخة على الخادم، ولا يستخدم `force-push`.

## الاستخدام

من جذر المستودع:

```bash
chmod +x scripts/publish-main.sh
scripts/publish-main.sh
```

بعد نجاح الاختبارات سيعرض السكريبت commit المراد دفعه. يجب كتابة النص التالي حرفيًا للموافقة:

```text
PUBLISH_MAIN
```

أي إدخال آخر يلغي العملية.

## ما ينفذه السكريبت

ينفذ السكريبت الخطوات الآتية بالترتيب:

1. يتحقق من وجود `git` و`pnpm`.
2. يتحقق من أن الفرع الحالي هو `main`.
3. يتحقق من نظافة شجرة العمل.
4. يشغّل `pnpm check`.
5. يشغّل `pnpm test -- --reporter=dot`.
6. يجلب آخر `origin/main`.
7. يرفض النشر إذا احتوى الخادم على commits غير موجودة محليًا.
8. يطلب تأكيدًا صريحًا قبل الدفع.
9. ينفذ `git push origin main` دون `--force`.
10. يتحقق من أن commit الخادم يساوي commit المحلي الذي تم اختباره.

## حالات الرفض المقصودة

يتوقف السكريبت إذا كانت هناك ملفات غير ملتزمة، أو إذا كان الفرع الحالي غير `main`، أو إذا كان `origin/main` قد تقدم. في الحالة الأخيرة يجب تنفيذ المزامنة يدويًا، وحل أي تعارض، ثم إعادة الاختبارات وتشغيل السكريبت من جديد.

لا يطبق السكريبت ترحيلات قاعدة البيانات. يجب تشغيل `pnpm db:push` بصورة منفصلة على بيئة تطوير مع `DATABASE_URL` معروف وآمن، ثم تشغيل السكريبت بعد نجاح التحقق من قاعدة البيانات.

## تغيير remote أو branch

يمكن تغيير القيم عند الحاجة دون تعديل الملف:

```bash
PUBLISH_REMOTE=origin PUBLISH_BRANCH=main scripts/publish-main.sh
```
